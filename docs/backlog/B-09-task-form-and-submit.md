# B-09 — Форма задачи: схема, дерево, сабмит и патч

Самая опасная часть протокола, и потому самая ценная для эксперимента. Иерархии формы —
`FormFieldDefinition`, `ValidationRule`, `FieldValue`, `FormCondition` — расширяемы, но **не
деградируют**: неизвестный `type` ломает разбор всего ответа, а не одного поля (§2.2). В Kotlin
неверный тип не собирается; в Go это обычная строка.

- **Каждый ответ вида `form` валидируется профилем в тестах сервера, до того как его увидит
  клиент.** Это единственная замена компилятору, которой Go-сторона располагает. Отдельно нужен
  тест на то, что валидатор действительно отвергает выдуманный тип: без него проверка была бы
  пустой — «сериализатор нашёлся» верно для любого имени, если где-то есть фолбэк.
- Связность `fieldId` (§9.2, §9.3) обеспечивается структурно: компонент ввода и определение поля
  создаются одним вызовом, чтобы нарушение было невыразимо, а не ловилось проверкой.
- Срок задачи — `text_field` с правилом `regex`; `required` ставится первым, потому что `regex`
  пропускает пустое значение (§9.5).
- Не покрывает: собственный тип поля для даты — [B-12](B-12-date-field-module.md).

- AC: проверка `form-fields` набора TCK находит цели и проходит; выдуманный тип поля отвергается
  тестом сервера; сабмит отвечает `KompotAction`, а не пустым `200`.
- Anchors: `server/internal/forms/`, `server/internal/http/forms.go`.

**Закрыто 21.08.2026.** Форма создания задачи (`form`), её сабмит и сабмит переноса из `perform`
(оба вида `submit`), плюс доска как `screen`.

**Связность обеспечена структурно, а не проверкой.** `forms.Builder` регистрирует определение поля и
возвращает компонент **одним вызовом**: поставить инпут, не объявив поле, невыразимо, и объявить
поле, которого форма не показывает, — тоже. Тест сверяет обе стороны и падает, если множества
разойдутся.

**Валидация профилем работает и не пуста.** Каждый ответ проверяется схемой этой сборки; отдельный
тест скармливает валидатору правдоподобные выдумки — `date_field`, `date_value`, `tabs` — и требует
отказа, а следом требует, чтобы объявленные типы принимались: валидатор, отвергающий всё, этот файл
не пройдёт.

**Порядок правил.** `required` первым, `regex` вторым — регулярка пропускает пустое значение, чтобы
необязательное поле можно было оставить пустым, и порядок решает, какое сообщение увидит человек.

просмотр вперёд, а Go-регэкспы его не поддерживают вовсе — валидатору подставлен ECMA-совместимый
движок.
