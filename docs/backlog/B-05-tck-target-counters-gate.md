# B-05 — Гейт формулируется по счётчикам целей TCK, а не по отсутствию находок

README набора проверок говорит прямо: проверка, не нашедшая ни одного подходящего эндпоинта,
проходит молча, и без счётчиков целей зелёный прогон ничего не значит. Для tacku это не мелочь, а
способ провалить главную цель, выглядя успешно: восемь проверок против сервера, у которого нет ни
пагинации, ни ETag, ни идемпотентности, дадут чистый отчёт, доказывающий ноль.

- **Гейт — «у каждой из восьми проверок хотя бы одна цель», а не «находок нет».** Второе условие
  выполняется тривиально и потому бесполезно; первое ловит именно ту ошибку, которая здесь наиболее
  вероятна.
- Отвергнуто: сравнивать число целей с ожидаемым числом. Ожидаемое число само пришлось бы
  поддерживать руками, и разошлось бы оно молча — ровно та болезнь, которую гейт лечит.
- Не покрывает: канал живых обновлений. Переносимой проверки на него нет, и это отдельный открытый
  вопрос ресёрча.

- AC: прогон против сервера, у которого нарочно отключён один вид эндпоинтов, красный — и в выводе
  названо, какая проверка осталась без целей.
- Anchors: `client/tck/`, `.github/workflows/`.

**Закрыто 21.08.2026.** `client/tck` — модуль `TckGate`, судящий отчёт в **две стороны**:

1. У каждой из восьми проверок хотя бы одна цель. Это то, ради чего задача заводилась.
2. Ни одной проверки, о которой гейт не знает. Если набор обзаведётся девятой, гейт, искавший
   восемь, продолжил бы проходить, покрывая меньше, чем заявляет, — тихое сужение хуже громкой
   поломки.

Находки, разумеется, тоже роняют прогон: B-05 добавляет условие, а не заменяет прежнее.

Имена восьми проверок вынуты **из опубликованного артефакта**, а не из его README: строковые
литералы в `TckRunner` — это то, что реально попадает в `exercised`, а README мог бы отстать.
Счётчики печатаются и на зелёном прогоне: число — единственное, что отличает проверку, которая
посмотрела и не нашла, от той, которая не смотрела.

Судится отчёт, а не сервер, поэтому модуль собран и проверен до того, как появился хоть один
эндпоинт. Обе стороны гейта прогнаны **мутацией**: обнулённый список непроверенных роняет три теста,
обнулённый список неизвестных — четвёртый.

Живая половина исходного критерия приёмки — прогон против сервера с нарочно отключённым видом
эндпоинтов — переезжает в [B-14](B-14-tck-harness-and-run.md): к тому моменту судья уже будет
проверен отдельно от подсудимого.
