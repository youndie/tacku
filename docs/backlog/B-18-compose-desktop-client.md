# B-18 — Клиент на Compose Desktop поверх опубликованных модулей kompot

Приложение-прототип: окно на JVM, рендер дерева экрана готовыми модулями kompot
(`kompot-client` и рендереры плагинов формы и картинок), тема через `kompot-ds-material-compose`.
Своего кода — сборка, вход, конфигурация адреса и набор токенов дизайн-системы.

- **Клиент здесь — измерительный прибор, а не продукт.** Он самая обкатанная часть системы, поэтому
  расхождение, которое он показывает, почти наверняка на стороне сервера. Из этого следует
  дисциплина: не чинить клиент, чтобы «заработало», а сначала выяснять, кто из двоих неправ по
  спеке.
- Набор токенов объявляет клиент и публикует обычными константами (§6); сервер обязан использовать
  именно их, а не выдумывать строки. Значит набор появляется до экранов — см.
  [бриф дизайнера](../design/design-brief.md) §4.
- Клиент обязан пережить неизвестный тип компонента заглушкой (§2.1); заглушку надо нарисовать, а не
  оставить на усмотрение рендерера.
- Не покрывает: iOS и Android. Прототип десктопный.

- AC: приложение открывает доску и карточку задачи с живого Go-сервера; неизвестный тип компонента
  даёт заглушку, а не пустой экран; неизвестный токен даёт значение по умолчанию и предупреждение в
  лог.
- Anchors: `client/app/src/`, `client/app/build.gradle.kts`.
