# B-14 — Харнесс TCK и первый прогон против Go-сервера

Момент, ради которого затеян проект: набор проверок, написанный для Kotlin-реализации, направляется
на сервер, у которого с ней нет ни строчки общего кода. Харнесс — маленький JVM-модуль: отдать
`TckConfig` свою спеку, своё описание HTTP и адрес живого сервера.

- **Красный первый прогон — нормальный исход, а не срыв.** Ценность в том, **где** он красный:
  каждый пункт сперва читается как вопрос «а написано ли это где-нибудь, кроме кода Kotlin-реализации»
  и только потом как дефект Go-сервера. Иначе набор превращается в инструмент подгонки под чужую
  реализацию, и эксперимент перестаёт что-либо измерять.
- Проверка `idempotency` выполняет **реальную операцию** — README набора предупреждает отдельно, —
  поэтому прогон идёт против тестового стенда, а не против чужих данных.
- Отчёт печатает счётчики целей; гейт по ним — [B-05](B-05-tck-target-counters-gate.md).
- Не покрывает: канал живых обновлений, `text/event-stream` в слепой обход не входит.

- AC: прогон доходит до конца и печатает отчёт; каждая из восьми проверок имеет хотя бы одну цель;
  каждая находка классифицирована в [журнале вопросов](../research/questions.md) как дефект сервера,
  дыра спеки или законная свобода.
- Anchors: `client/tck/src/test/kotlin/`, `server/cmd/tacku/`.

**Первый обход состоялся 21.08.2026, и он красный по двум разным причинам.** Задача остаётся
открытой; ниже — что уже работает и что мешает.

`make tck` поднимает фикстурный сервер авторизации (`cmd/devauth`, вне продукта намеренно: минтер
токенов в том же бинаре — это чёрный ход с флажком), поднимает сервер, гоняет набор и гасит обоих.

Отчёт первого обхода:

| Проверка | Целей | Итог |
|---|---|---|
| `schema` | 3 | прошла |
| `component-id` | 3 | прошла |
| `etag` | 1 | прошла |
| `navigation` | 1 | прошла |
| `pagination` | 1 | прошла |
| `auth-required` | 3 | **три находки — артефакт харнесса** |
| `form-fields` | 0 | целей нет |
| `idempotency` | 0 | целей нет |

**Про `auth-required`.** Набор добывает учётные данные сам, через `loginPath`, а формы входа у этой
сборки нет — значит отдать ему токен поддержанным способом нечем. Харнесс подставляет заголовок во
все запросы, и это закрывает семь проверок, но ломает восьмую: `auth-required` ходит на эндпоинт
нарочно без токена, заголовок приезжает всё равно, и увиденные ей `200` настоящие. **Находки —
это ложь харнесса набору, а не дефект сервера**; проверено анонимным обходом, где те же три
эндпоинта отвечают `401` правильно. Честное лечение — эндпоинт входа, то есть B-09.

**Про две проверки без целей.** Форм и сабмитов пока нет; это ровно то, ради чего
[B-05](B-05-tck-target-counters-gate.md) считает цели, а не находки. Зелёный отчёт без них означал бы
ноль.

**Что дал обход по существу.** Одна правка описания: `security` объявлен **на операции**, а не только
в корне документа. Пока он стоял только в корне, `auth-required` находила ноль целей и **проходила
молча** — то есть описание, формально верное, делало проверку бесполезной. Это и есть та ошибка,
против которой гейт написан, и нашлась она первым же прогоном.

**Второй обход 21.08.2026: девять проверок из девяти имеют цели, находок о сервере ноль.**

| Проверка | Целей |
|---|---|
| `schema` | 5 |
| `perform` | 5 |
| `auth-required` | 5 |
| `component-id` | 5 |
| `etag` | 2 |
| `form-fields` | 1 |
| `idempotency` | 1 |
| `navigation` | 1 |
| `pagination` | 1 |

Остались пять находок `auth-required`, и все они — известное враньё харнесса набору: токен
подставляется во все запросы, включая те, что набор делает нарочно анонимными. Лечится эндпоинтом
входа; задача остаётся открытой ровно на это.

**Обход нашёл два настоящих дефекта, которых не видели юнит-тесты** — оба потому, что тесты сеют
данные, а стенд начинается с пустой базы:

1. Пустое рабочее пространство отдавало **404** на экране доски. Дизайн предусмотрел там пустое
   состояние; теперь оно и отдаётся.
2. Проверка идемпотентности получала `404` вместо `409`. Причина глубже симптома: первый сабмит
   падал за отсутствием доски, а неудачная попытка намеренно не запоминается — значит конфликт,
   которого она ждала, не мог случиться вовсе. Появилась команда `tacku seed`.

**Третий обход: девять проверок, все с целями, одна находка — и её сервер починить не может.**

Форма входа появилась, и набор теперь **входит сам**, через `loginPath`: он держит учётные данные и
решает, какие запросы их несут, поэтому пробы `auth-required`, задуманные анонимными, такими и
остаются. Пять находок прошлого обхода исчезли — они были враньём харнесса, как и было записано.

Осталась одна: `/forms/sign-in` объявлена публичной (`security: []`), а проверка всё равно ждёт от
неё `401`. Ирония кольцевая — набор требует `loginPath`, до сабмита нужно получить форму, а форму он
считает дефектом. Задано вопросом наверх ([Q-17](../research/questions.md)); задача остаётся открытой
ровно на этот ответ.

**Закрыто 21.08.2026. `TCK: passed`.**

| Проверка | Целей |
|---|---|
| `schema` | 6 |
| `component-id` | 6 |
| `perform` | 6 |
| `auth-required` | 5 |
| `etag` | 2 |
| `form-fields` | 2 |
| `idempotency` | 1 |
| `navigation` | 1 |
| `pagination` | 1 |

Девять проверок, у каждой есть цели, находок ноль. Набор, написанный под Kotlin-реализацию, обошёл
сервер на Go, написанный по опубликованному контракту и без чтения этой реализации, и не нашёл
расхождений.

**Что до этого довело — четыре обхода, и каждый находил своё:**

1. Анонимный: описание объявляло `security` только в корне, `auth-required` находила ноль целей и
   **проходила молча**. Ровно тот дефект, против которого написан гейт
   [B-05](B-05-tck-target-counters-gate.md), и нашёлся он первым же прогоном.
2. С подставленным токеном: пустое рабочее пространство отдавало `404` вместо пустого состояния, а
   проверка идемпотентности получала `404` вместо `409` — потому что первый сабмит падал за
   отсутствием доски, а неудачная попытка намеренно не запоминается.
3. С формой входа: осталась одна находка, и её сервер починить не мог — публичный эндпоинт нечем
   было объявить ([Q-17](../research/questions.md)).
4. После ответа наверху — чисто.

**Цена честности гейта видна отдельно.** Ни один из четырёх обходов не был бы красным, если бы
приёмка считалась по отсутствию находок: первый прогон был бы зелёным при нулевом покрытии.
