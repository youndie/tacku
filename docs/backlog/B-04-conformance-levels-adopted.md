# B-04 — Зафиксировать, какие уровни соответствия tacku принимает, а какие нет

`SPEC.md` §17 перечисляет несколько независимых уровней проверки реализации, и tacku может принять
не все. Уровень «корпус эталонных тел покрывает **каждый** тип профиля» честно не выполним: профиль
приедет с денежными типами из `form-standard`, а трекер не отправит ни одного такого значения
([research §1.3](../research/research-architecture.md#13-словарь-полей-знает-про-деньги-и-не-знает-про-даты)).

- **Уровень не принимается, и причина записывается.** Альтернатива — придумать денежные образцы ради
  процента покрытия — даёт корпус, который ничего не отражает, и зелёную проверку, которая ничего не
  значит. Отказ с названной причиной честнее и дешевле.
- Отвергнуто: вырезать денежные типы из профиля. Профиль собирается из модуля целиком; выбрать
  половину `form-standard` нельзя, не расщепив модуль в kompot.
- Не покрывает: сам прогон проверок. Здесь только список того, на что мы заявляемся.

- AC: в репозитории есть файл, перечисляющий уровни §17 с отметкой «принят / не принят» и причиной у
  каждого непринятого; на него ссылается `README.md`.
- Anchors: `docs/research/research-architecture.md` (§1.3), `client/tck/`.
