# B-30 — Читать бэклог docs-as-code как доску: git — хранилище, tacku — вид и аренда

Бэклог метода docs-as-code — это **уже трекер**: файл на задачу, во фронтматтере `id`, `status`
(`open` / `wip` / `done` / `question` / `dropped`), `priority`, `size`, `stage`, `epic`,
`blocked_by`, плюс генерируемый индекс. Хранилище — git, интерфейс — markdown-таблица. Домен тот же,
что у tacku; отличается подложка.

- **Направление связи решает всё.** Источник истины остаётся в git: задачи цитируются по
  идентификатору из документов всех слоёв, ревьюятся в PR и живут рядом с кодом, который описывают.
  tacku поверх — **вид** и одна служба, которой у git нет (ниже). Обратное направление — держать
  задачи в базе tacku и выгружать в файлы — убивает ровно то, ради чего метод существует.
- **Разделение, на котором всё держится: git владеет тем, что должно пережить; tacku — тем, что
  должно протухнуть.** «Задачу B-14 сейчас делает агент X, аренда до 14:32» — состояние с высокой
  частотой обновления и обязательным сроком годности. В файл его класть нельзя: получится коммит
  раз в полминуты, а упавший агент оставит `wip` навсегда. Поэтому поле исполнителя во фронтматтере
  заводить **не** нужно — нужна аренда с сердцебиением в хранилище tacku.
- **Что это чинит из уже оплаченного.** Две параллельные ветки занимают один номер задачи и git
  сливает их молча — это случалось. `claim_task` с арендой выдаёт номер один раз. Плюс «что
  изменилось с прошлого раза» для человека, надзирающего за несколькими агентами, — тот же курсор,
  что и у агента.
- **Продуктовый смысл важнее технического.** Тезис tacku — «агент участник команды, происхождение
  видно всегда» — проверяется здесь на настоящей нагрузке: первые пользователи доски это автор,
  смотрящий на своих же агентов. Вымышленная команда такой проверки не даёт.
- **Чего делать нельзя.** Это не первая веха и не замена хранилища. Приёмочная цель проекта —
  прогон TCK против сервера, написанного по спеке; git-адаптер меняет
  [B-07](B-07-domain-core-and-change-log.md) целиком и увёл бы проект в сторону. Единственное
  следствие для сегодняшнего дня — **не давать деталям SQLite протечь в домен**, что и так записано
  ценой решения D9.
- Не покрывает: запись в git из доски. Первый шаг — только чтение плюс аренда; коммит с доски
  упирается в конфликт по генерируемому индексу, и это отдельный разговор.

- AC: решение записано; если «да» — доска показывает задачи репозитория с их `stage` в колонках,
  занятая задача называет агента и время аренды, брошенная аренда истекает сама, а исходный
  репозиторий остаётся единственным местом, где задача меняется по существу.
