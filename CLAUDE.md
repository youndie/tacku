# tacku — инструкции для агента

## С чего начинать сессию

1. [`docs/research/research-architecture.md`](docs/research/research-architecture.md) — почему всё
   устроено так. Задача, прочитанная мимо ресёрча, выглядит как «сделай очевидное», а очевидное
   здесь часто неверно: у проекта две цели, и вторая объясняет половину решений.
2. [`backlog.md`](backlog.md) — порядок работ, этапы и решения, которые не нужно перерешивать.
   Сама задача — файл в [`docs/backlog/`](docs/backlog/).
3. Документ того слоя, к которому относится задача — сегодня это ресёрч, журнал вопросов и
   [`docs/services/server.md`](docs/services/server.md). Слоёв фич, экранов и API по-прежнему нет
   намеренно: документ, написанный раньше того, что он описывает, излагает намерение как факт.

## Барьер — главное правило репозитория

**Go-сервер пишется по опубликованному контракту KOMPOT, а не по его Kotlin-исходникам.**

Разрешено читать: `SPEC.md`, файлы схемы (`schema/*.json`), README набора `kompot-tck`, эталонный
корпус тел. Ровно это получил бы сторонний разработчик.

Запрещено: `*.kt` реализации kompot. Чекаут лежит отдельным каталогом вне этого репозитория и в
него не копируется.

**Вопрос, ответа на который нет в контракте, записывается в
[`docs/research/questions.md`](docs/research/questions.md) до того, как решается.** Заглянуть в
Kotlin, чтобы снять вопрос, — событие журнала, а не способ его закрыть. Журнал и есть результат
приёмочной половины проекта; Go-код — побочный продукт.

Правило целиком — [ресёрч §0](docs/research/research-architecture.md#0-правило-барьера).

## Что считается сделанным

- **Веха не закрывается по проценту.** Прогон `kompot-tck` зелёный ничего не значит сам по себе:
  проверка, не нашедшая ни одной цели, проходит молча. Смотреть счётчики целей
  ([B-05](docs/backlog/B-05-tck-target-counters-gate.md)).
- **Красная находка сначала классифицируется, потом чинится.** Три класса: дефект нашего сервера,
  дыра спеки, законная свобода реализации. Чинить Go, пока не позеленеет, — способ превратить набор
  проверок в инструмент подгонки под чужую реализацию.
- **Число, которого не измеряли, не пишется.** Измеренное называет, что и как мерили.

## Проверки

```bash
make check
```

Гейт: индекс бэклога, связность документов, карта покрытия, обе половины кода. CI гоняет ровно это
же — набор, который локально отличается от CI, делает «здесь зелено, там красно» нормой.

Скриншоты сверяются по пикселям и в этом наборе тоже. Их две группы, и разница между ними важна:
`States`/`Diagnostics` — рисованные вручную куски, каждый про одну вещь; `Screens` — настоящие
экраны, снятые с тел, которые отдал засеянный сервер (`make screens` обновляет тела, `make shots`
переснимает картинки). Второй группы не было до августа 2026, и её отсутствие стоило дорого:
дефект, живший на каждом экране и ни на одном из кусков, был не виден никому
([Q-58](docs/research/questions.md)).

**Голден не умеет сказать «правильно», он говорит «как в прошлый раз».** Первая запись освящает то,
что было на экране. Поэтому картинка, устроенная как сравнение (крашеный сервером блок рядом с
нарисованным тулкитом контролом), стоит больше десяти обычных: её нельзя молча переснять.

**Голдены переносимы между машинами, но не сами по себе:** обвязка обязана рисовать шрифтом, который принесла с собой (`ViddikFontFamily` и
`ViddikPlatformTextStyle`), а не тем, что нашёлся на машине. Стиль без семейства даёт картинку
машины, а не кода; с ним запись на macOS/arm64 и на Linux/amd64 совпадает побитово — 0 различных
пикселей на всех снимках ([B-34](docs/backlog/B-34-viddik-screenshots.md)).

```bash
make probes
```

Перепрогон проб, на которых держатся факты ресёрча. Проба, переставшая собираться, — это
изменившийся факт: сверьтесь с ресёрчем и поправьте там, а не в пробе.

## Где что собирается

**Обе половины собираются локально на маке.** Правило «Kotlin уходит на сборочную Linux-машину»
касается репозиториев, синхронизируемых mutagen; tacku в списке синхронизации нет, поэтому оно не
применяется. Проверено запуском обеих: `go test` — секунды, `:spec-gen:test` — около двух.

```bash
make check     # гейт: доки, Kotlin-половина, Go-половина — ровно то, что гоняет CI
make format    # ktlint и gofmt на месте
make spec      # перегенерировать спеку сборки; правит файлы в spec/, поэтому вне гейта
```

Форматтеры — часть гейта на обеих половинах: `ktlint` на Kotlin, `gofmt` на Go. Оба проверены тем,
что им скармливали кривой код, а не тем, что они «настроены».

Если tacku когда-нибудь попадёт в mutagen, вопрос открывается заново: реплика на Linux — не место для
работы, а каталоги сборки под синхронизацию попадать не должны.

Обе зависимости версий жёсткие и не наши: kompot опубликован под **JVM 25** (на 21 резолв падает),
MCP-SDK требует **Go ≥ 1.25**.
